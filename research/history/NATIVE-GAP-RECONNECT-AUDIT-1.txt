6. WHAT "Timeline publishable" CERTIFIES
======================================================================

ReconcileTimeline:
  unpublishable → notify healing → loop reconcileAllKlineGaps(force=true)
  until framesTimelineHealthy OR max tries → finalizeTimelineHealFlush.

framesTimelineHealthy: EVERY native Frame, KlineSeriesNeedsGapFill through
Cap last CLOSED open (not the forming bar).

healFillClosedGapsBeforeFlush: native only; Exact REST between Frame tip and
pending tip if pending skips ≥1 closed open. Forming pending (pending == next
open after tip) → need=false, no Exact fill of the forming bar.

finalize: drain pending, applyTick each, framesSeriesContiguous (every native,
consecutive NextBarOpen, NO Cap — still closed series only), pending empty
→ timelinePublishable=true → notifyTimelinePublishable.

HealProbe logs only m.timeframe (work TF, default 1m), ChartTimeSec of last 10
opens. Telemetry choice. Not "heal 1m only."

Grok forming-bar hypothesis vs code: CORRECT as a timing statement.
At 06:45:35, last CLOSED 5m = 06:40; forming 5m = 06:45. Publishable does not
require the forming 5m to be a closed sqlite row. It requires native closed
series contiguous through Cap.

At audit time the 06:45 5m IS closed in sqlite and matches REST, so that bar
was recovered later (WS after publishable, and/or periodic REST). Path not
logged as "heal closed fill" in the user paste (success REST merge is mostly silent).

  browser WS close
    → 3s
    → FE HEALING + 25s watchdog + "Synchronizing live data…"
    → new socket welcome + subscribe
    → no publishable edge

publishability is STATE on the backend (atomic.Bool) and EDGE EVENT on the wire.
FE recovery waits for the edge. Hard refresh: new JS machine in LIVE until a
healing enter; does not query publishable state.

across extra reconnects.
