3. CORRECTIONS TO THE AUDIT PROMPT
============================================================

The prompt is mostly right. These points must not be implemented
as written.

3.1 Do not invent RawCoordinateClause and RelationClause kinds.

    Frozen starlens already has KindContinuous with Field, Cmp,
    Bound. Outcome fields, Schema 3 coordinates, and Matrix
    relations must enter that same kind.

    New kinds named after the source artifact would become a
    second and third engine in everything but name.

    Stable IDs (section 6 and 8) go in Clause.Field.
    Observation is looked up by that ID. Comparison stays the
    same Cmp tokens: >  >=  <  <=.

3.2 Width is not "Present AND finite" the way VWEMA is.

    Volume-channel Width is stored only when ValuesOK is true
    (all of VWEMA, ChanMid, ChanUp, ChanDn finite). WidthOK
    is then true. The evaluator uses Present AND WidthOK.
    It does not re-derive width in the browser.

    Close-channel width uses CloseWidthOK, which is CloseUpOK
    AND CloseDnOK. It does not use ValuesOK.

3.3 ValuesOK is not a coordinate.

    It is an aggregate gate used to write Width and Distance.
    It is not in the 142. Filtering on ValuesOK would be a new
    categorical clause, not a numeric coordinate.

3.4 TVDirection, TVConfirmedAt, Present, OpenTime, CloseTime
    are not among the 142.

    TVAge is the only TV numeric coordinate. TVDirection remains
    a category (later Kind if a consumer exists; not this 191).

3.5 EMA12 acceleration is not missing from the 142.

    StarTF stores Ema12 and Ema12Slope only. readStarTF discards
    the accel return from projectSample. Signal acceleration is
    also not stored. Those absences are frozen Schema 3, not
    audit omissions.

3.6 Discovery P20/P40/P60/P80 are not Lens defaults.

    They are descriptive five-slice views on the discovery
    period. A Lens bound is an explicit user cut. Do not copy
    discovery edges into Clause.Bound.

3.7 The prompt's example "VWEMA(15m) - VWEMA(1h)" is a Matrix
    relation ID (M15H1Vwema), not two raw fields subtracted in
    the browser.

3.8 Current Provenance (forecast/starlens/population.go) stores
    Schema3Digest, Schema3Commit, OutcomeDigest only.

    That is correct for outcome-only populations. Matrix clauses
    require additional fields on the same Provenance object
    (section 16). Do not invent a second provenance type.

7. RAW OBSERVATION FAMILIES
============================================================

Family A — lineFinite (Present AND finite). ValuesOK is NOT the gate.

    TF.Vwema, TF.ChanMid, TF.ChanUp, TF.ChanDn

    Present false → missing (stored 0 is not a reading).
    Present true, non-finite → missing.
    Present true, finite 0 → observed zero.

    Test already frozen: M15.Vwema = 0, ValuesOK false, Present true
    is observed zero (star_discovery_test.go).

Family B — Present AND named OK flag (false OK stores 0, not a reading).

    Slope, Width, WidthChange, Distance,
    MidSlope, MidAccel,
    Ema5, Ema5Slope, Ema5Accel,
    Ema12, Ema12Slope,
    VwemaAccel,
    RsiClose, RsiCloseSlope, RsiCloseAccel,
    CloseMid, CloseUp, CloseDn, CloseWidth, CloseWidthChange,
    Ema7, Ema7Slope, Ema7Accel,
    Macd, MacdSlope, MacdAccel,
    root RSX family, H*RSX family, TVAge.

Family C — volume-channel width and distance (write-time).

    WidthOK and DistanceOK are set only inside ValuesOK
    (all four orange/VWEMA numbers finite). Then:

        Width    = ChanUp − ChanDn
        Distance = Vwema − ChanMid

    Evaluator observation: Present AND WidthOK / DistanceOK.
    Do not treat Width as observed merely because Vwema is finite.

Family D — close-channel width.

    CloseWidthOK := CloseUpOK AND CloseDnOK
    CloseWidth   := CloseUp − CloseDn
    CloseWidthChangeOK requires CloseWidthOK and a finite previous
    close-channel width.

    Independent of ValuesOK / orange channel.

Real zero vs missing (all families):

    OK true, value 0  → numeric observation; histogram includes it
    OK false          → missing; excluded from Values; clause fails
    Never coerce missing to 0.

9. TYPED CLAUSE MODEL
============================================================

No new Kind.

    Clause{
        Kind:  "continuous"
        Field: <outcome ID | Schema 3 ID | Matrix ID>
        Cmp:   ">" | ">=" | "<" | "<="
        Bound: float64   // 0 is a real bound; always stored
    }

Existing outcome Field names stay as they are
(entryPrice, mfeAtr, …).

Schema 3 Field names are the IDs in section 6
(e.g. M15.Vwema, H1RSX.Value, TVAge, RSXMinusSignal).

Matrix Field names are the IDs in section 8
(e.g. M15H1Vwema, H1RsxMinusSignal).

knownField expands to all 11 outcome + 142 + 49 names.
Unknown Field is a validate error.

key() remains "n:" + Field so two clauses on the same ID
share one picture (self-exclusion). Clauses on M15.Vwema and
M15H1Vwema are different keys.

Side, status, R, stop stay their existing kinds.
They may share a Lens with continuous coordinate clauses.

Example Lens (one Evaluate):

    KindContinuous Field=mfeAtr           Cmp=>= Bound=4
    KindContinuous Field=M15H1Vwema       Cmp=>= Bound=0
    KindContinuous Field=H4RSX.Value      Cmp=<  Bound=50

AND. Missing on any clause fails that row for Pass.

============================================================
10. EVALUATION SEMANTICS
============================================================

For a continuous clause on field F:

    n = row.Number(F)
    if !n.OK → fail
    compare n.Value to Bound with Cmp

Schema 3 Number(F) uses section 7.
Matrix Number(F) uses stored Rel.OK and Rel.Value.
Do not recompute Rel.

Pass membership is parent members that satisfy every clause.
Order remains parent/table order: decisionAt ascending.
Prev/Next walk that order. Do not sort by coordinate value.

Empty clause list: parent unchanged (frozen Evaluate).

============================================================
11. SELF-EXCLUSION AND PICTURES
============================================================

Same as outcome NumberPicture.

picture(F) is computed on:

    parent
    AND all clauses whose key() != "n:"+F

Then F's own bound produces Pass.

NumberPicture:

    Base     = size of that self-excluded set
    Missing  = count with !OK
    Values   = observed numbers only (zeros with OK stay here)

Do not put discovery slices on this picture.
Do not use a special Schema 3 or Matrix histogram rule.

============================================================
12. COMPARISON (VIEW, NOT AN ENGINE)
============================================================

Inputs:

    Population A
    Population B
    coordinate ID F
    shared bin edges (caller-supplied, strictly increasing)

Procedure:

    Evaluate A with its stored clauses (or current lens)
    Evaluate B the same way
    a = A.NumberPicture(F)
    b = B.NumberPicture(F)
    CountBins(a.Values, edges)
    CountBins(b.Values, edges)

Same F, same observation rule, same edges, same scale.

Display may show:

    distribution A / B
    missing A / B
    Base / observed counts
    pass membership lists already owned by each Population

Must not compute:

    separation, effect size, predictive power, "strength", "best"
    ranking of coordinates or populations
    automatic bin search
    holdout-driven selection of F, edges, or populations

Holdout may be displayed as composition (count of members with
decisionAt >= 1767225600000). It must not choose anything.
