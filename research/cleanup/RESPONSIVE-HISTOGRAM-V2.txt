3. CORRECTION
============================================================

V1 treated a bar click as Field >= from AND Field < to. That was
the wrong product: the user wanted click-as-slider, not bin
membership.

histSel is gone. clausesFromForm reads only the form bound.

OpenLow / OpenHigh remain display tags for which bin contains the
threshold. They are not Lens clauses.

============================================================
4. REPRESENTATIVE POLICY
============================================================

Every displayed bin has finite from and to (observed min/max of
the NumberPicture, not ±inf).

    representative = (from + to) / 2
    if from == to: that value

The browser uses server from/to only. Midpoint is a V1 click
policy, isolated in binThreshold. It is not a research constant.

Better than shipping a server `representative` field: the evaluator
never sees bins, so there is no research meaning to freeze on the
wire. Open tails already have finite display edges (observed min/max),
so a midpoint of the painted interval is defined without a new DTO.

Open-ended counting still uses CountHalfOpen for bar heights.
Click does not invent ±inf midpoints because the painted interval
is finite.

============================================================
5. CANONICAL STATE
============================================================

    Field + cmp + bound   (one KindContinuous)

Slider writes that bound.
Histogram click writes the same bound, then the slider and number
field show it, then Evaluate.

Yellow line = the bound on the min–max axis.
Containing bin is shaded; moving the slider inside the same bin
moves the yellow line, not back to the midpoint.

Header — / N is state.last.pass.length (walk length), not bin.count.
