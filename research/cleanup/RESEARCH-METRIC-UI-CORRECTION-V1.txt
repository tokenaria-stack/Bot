3. CORRECTIONS
============================================================

1. Microscope checkboxes removed.
   They had no consumer. They were not given a new job.
   Hierarchy, triangles, family colors, accel/slope/dot/value,
   collapse, and father-row value are unchanged.

2. Population tree color squares.
   Catalog rows called a hard-coded absent swatch. They now
   use StarInspectionSwatches.specs(Field ID) and
   DDRFactory.swatchHex — the same lookup as the microscope.
   FIELD leaf aliases live in that existing swatch file, not
   a second color table.
   Father: [color] [triangle] [checkbox] [name]
   Child:  [empty] [color] [checkbox] [short name]

3. Coordinate tree vertical resize.
   Handle is the bottom edge of .star-lens-cat-list only
   (data-coord-resize, ns-resize). Height clamp 120px .. 70vh.
   Preference key: localStorage star-lens-cat-height.
   Search, histogram, rail width, and microscope are untouched.

4. Wozduh Star click restored (regression, not a new selector).
   Cause: ChartAdapter.onWozduhClick subscribed the first
   callback and then returned true on later binds without
   updating the function. StarResearch.init also never retried
   bindChartClick after the inspection shell mounted.
   Fix: store _wozduhClickFn on the live chart state and call
   the current function from the existing subscribeClick
   handler. StarResearch.init() ends with bindChartClick().
   Selection is still StarResearch.onPaneClick → selectOpenTime
   → existing microscope onSelected. No second selectedStar.

The chapter prompt asked not to hard-code a new color table.

existing LINE keys is required because catalog IDs are Pascal
Field names and microscope IDs are lowercase reading ids.

before — not a second registry.
