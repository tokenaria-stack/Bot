2. FIRST MATRIX
============================================================

Clock. 15m numbers are the Star bar.
1h, 4h, and daily use the latest bar of that timeframe
whose close is at or before the Star close.
A relation uses those bars only.
If either side is not a real observation, the relation
is OK false and stores 0. That 0 is not a reading.
No fill. No future bar.

A line's own OK flag gates that line.
Orange mid is finite on its own. Do not require
ValuesOK, which also demands VWEMA and both bounds.
VWEMA is finite on its own. Distance already uses
ValuesOK and is left as stored.

VWEMA and orange mid have no OK field on the
snapshot. Do not add one. Schema 3 stays frozen.
Their observation is Present and a finite number.
An absent bar stores 0, and Present false keeps
that 0 from being read as a real zero.
ValuesOK is not the gate. A finite 0 with
ValuesOK false is still an observation.
Validity belongs to the operand. A tie of two
real readings is 0 with OK true. A missing
operand stores 0 with OK false, whatever the
other number is.

Unit for every level and every width is oscillator
points. Native slope is points per bar of that
timeframe. These lines are not prices.

--- Raw, kept as stored ---

Every schema-2 number stays, including both channel
bounds. Identity and bar times stay so a row can be
joined to the Star. They are not state relations.

Per timeframe, 30 numbers, on 15m, 1h, and 4h:

  VWEMA
  orange mid, upper, lower
  VWEMA slope                         field name Slope
  orange width, width change
  VWEMA − orange mid                  field name Distance
  orange mid slope, orange mid acceleration
  EMA5 value, slope, acceleration
  EMA12 value, slope
  VWEMA acceleration
  RSI close value, slope, acceleration
  close-channel mid, upper, lower, width, width change
  EMA7 value, slope, acceleration
  MACD line value, slope, acceleration
                                      the slot is already +50

15m RSX is the root block, not a field on M15:
  value, slope, acceleration, signal, signal slope,
  value − signal
1h and 4h RSX, five numbers each:
  value, slope, acceleration, signal, signal slope
TV direction and TV age stay 15m facts.
Side stays the Star side.

Count of raw numbers: 30×3 + 6 + 5 + 5 + TV age = 107.
Side and TV direction are categories, not numbers.

--- New relations, 15m / 1h / 4h ---

Same bar, same timeframe. Unit: oscillator points,
except the slope gap, which is points per bar of
that timeframe.

  EMA7 − MACD
      OK when Ema7OK and MacdOK
  EMA7 − close-channel mid
      OK when Ema7OK and CloseMidOK
  RSI close − close-channel mid
      OK when RsiCloseOK and CloseMidOK
  VWEMA slope − orange mid slope
      OK when SlopeOK and MidSlopeOK
      This is the slope of Distance.
      Do not store a second Distance column.

  1h RSX − 1h signal
  4h RSX − 4h signal
      OK when that timeframe's value and signal are OK
      15m already has RSXMinusSignal. Do not add another.

Neighbor levels. Lower timeframe minus the next
higher one. Unit: oscillator points.
Pairs: 15m−1h and 1h−4h.
Eight lines: orange mid, VWEMA, EMA5, EMA12,
RSI close, EMA7, MACD, RSX.
OK when both endpoints are finite.
16 columns.

Neighbor widths. Same pairs. Volume-channel width
and close-channel width. Unit: oscillator points.
OK when both WidthOK, or both CloseWidthOK.
4 columns.

New columns before daily: 4×3 + 2 + 16 + 4 = 34.

Do not add 15m−4h. It equals (15m−1h) + (1h−4h)
when all three bars are present.

3. DEFERRED
============================================================

Real arithmetic. Not in the first matrix.

Points per hour, then the neighbor gap of those
rates. Convert first:

  15m slope × 4
  1h slope × 1
  4h slope ÷ 4
  daily slope ÷ 24    only after schema 3

Then subtract neighbors. Apply this to the slopes
that already exist: orange mid, VWEMA, EMA5, EMA12,
RSI close, EMA7, MACD, RSX, and RSX signal.
OK when both native slopes are OK.
The converted slope is points per hour.
The gap is points per hour.

Width ratio, neighbor only:
  width_lower / width_higher
OK when both widths are OK and the higher width
is greater than 0. A higher width of 0 is OK false,
not an infinite ratio. Volume channel and close
channel. Dimensionless.

Level gap / width of the lower timeframe.
Same eight lines as the level gaps.
OK when the gap is OK and that lower width is OK
and greater than 0. Unit: widths of that channel.
Orange, EMA5, and EMA12 use the volume-channel width.
RSI close, EMA7, and MACD use the close-channel width.
VWEMA and RSX have no private channel. Their scale
form uses the volume-channel width, and the audit
marks that choice as a convention, not a law of the
indicator. Leave this whole family out of the first
matrix so the convention is not baked in early.

Cross-timeframe acceleration. Native acceleration is
points per bar squared, and the bars differ.
A common clock would be points per hour per hour,
which needs the square of the same factors
(15m × 16, 4h ÷ 16, daily ÷ 576).
That family is noisier than the slope family.
Defer it until a named question asks for it.

Signal level gaps across timeframes, and EMA12
acceleration. EMA12 acceleration was left out of
schema 2. A cross-timeframe signal gap can be added
later by the same neighbor rule. Neither is required
to state the first hierarchy.

Bars since a cross.
