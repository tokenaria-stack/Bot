A. SEMANTIC LAW (frozen)
----------------------------------------------------------------------

Native / exchange candles (futures REST, futures WS, Vision, spot REST/Vision):

    Kline.Volume ≡ BaseVolume
                 ≡ Binance total BASE asset volume
                 ≡ REST array index 5 ≡ WS JSON "v" ≡ Vision CSV column 5

    BTCUSDT units = BTC

    NEVER: taker-buy base "V", quote "q", taker-buy quote "Q"

Reserved, not implemented (no consumer this chapter):

    TakerBuyBaseVolume ≡ Binance "V"
    Future sources: native kline V, or aggTrade side+Qty
    Do not add the field to Kline / SQLite / q/Q / buy_fraction / imbalance.

Micro / 1s (SecondBarBuilder → micro_klines):

    Kline.Volume ≡ MicroTradeBaseVolume
                 ≡ sum of Qty for ALL observed aggTrades in that second

    Side (IsBuyerMaker / "m") is parsed then dropped. Changing m does not
    change Volume. This is NOT Binance "V" and is NOT claimed equal to
    native kline "v" without a separate source-parity test.

Sparse seconds (5s–45s) and derived minute/hour views:

    parent.Volume = sum(child.Volume) inside ONE semantic stream only.
    Never mix BaseVolume with TakerBuyBaseVolume.

WozduhBitVolBase:

    DAG compute-mask bit: volume-based Wozduh work is required.
    NOT Binance field "V".

MAX (Ingress equal-authority + SQLite UPSERT):

    Legal only when both old and incoming are the SAME semantic
    (BaseVolume on native; MicroTradeBaseVolume on micro).
    MAX is not v/V coercion, not quote/base coercion, not repair.

Wozduh next chapter (not this one):

    WozduhVolumeSource = certified BaseVolume on native closed candles.
    Do not substitute V, quote, or 1s micro proxy unless a future spec says so.
    BLOCKED until this ledger is GREEN.

RSX / FeatureTape2 / Brain3: untouched.

WS BUG (fixed in this chapter, production parse):

    encoding/json matches struct tags case-insensitively.
    json:"v" binds both "v" and "V"; the later key in the object wins.
    Binance kline payloads include both. A struct unmarshal can store taker-buy V
    in Kline.Volume. Production now uses a case-sensitive map and reads "v" only.
    Fixture TestEncodingJSON_StructTagVIsCaseInsensitive documents the language trap.

    Live SQLite tip still shows V because the running bot / already-written rows
    were produced by the old parser (and REST has not overwritten those tips).
    Archive history before the WS-only tip is overwhelmingly TOTAL_BASE.

No producer writes q or Q into Kline.Volume.
